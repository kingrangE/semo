# 웹 채팅과 HTTP API

CLI에서 사용하던 검색·출처 기반 답변을 브라우저에서도 사용할 수 있습니다. `semo/chat.py`의 동일한 처리 흐름을 CLI와 FastAPI가 함께 사용합니다. 별도의 프런트엔드 프레임워크나 빌드 과정 없이 HTML·CSS·JavaScript를 API 서버에서 제공합니다.

## 실행

기존 `.env`의 `OPENAI_API_KEY`, `OPENAI_CHAT_MODEL`, `POSTGRES_PASSWORD`를 유지합니다. ChromaDB v2 색인에 자료가 들어 있어야 실제 답변을 받을 수 있습니다.

```sh
docker compose up --build -d api
```

브라우저에서 **http://localhost:8001**을 열면 됩니다. API 문서는 **http://localhost:8001/docs**, 서버 로그는 다음 명령으로 확인합니다.

```sh
docker compose logs --tail=100 api
```

`api`는 기존 Dockerfile과 Python 의존성을 재사용하고, Airflow 프로세스와 별도 컨테이너에서 실행합니다. ChromaDB를 조회하며 PostgreSQL이나 원문 파일을 수정하지 않습니다. 기존 수집·색인 DAG는 그대로 사용합니다.

## 화면에서 할 수 있는 일

- 질문 예시 선택·질문 입력·답변 확인.
- 답변별 공식 출처와 게시일·답변 기준일 확인.
- 종료된 학사일정을 검색에 포함할지 선택.
- 답변 대기·연결 오류·요청 지연 안내.
- 현재 탭의 질문·답변 화면 지우기.

질문은 1~1,000자로 제한합니다. Enter로 전송하고 Shift+Enter로 줄을 바꿉니다. 한글 조합 확정 Enter는 전송으로 취급하지 않습니다. 답변을 기다리는 동안 중복 전송은 막습니다. 답변과 출처 제목은 HTML로 해석하지 않고 텍스트로 표시합니다.

최근 5회의 완료된 질문·답변을 현재 탭의 메모리에 유지하고 후속 요청의 `conversation`으로 전달합니다. LocalStorage·쿠키·대화 DB는 사용하지 않으며 새로고침이나 대화 지우기로 초기화합니다. 실패한 요청은 맥락에 넣지 않습니다. API 키는 브라우저에 전달하지 않습니다.

대화가 있으면 같은 답변 모델이 `semo.rewrite` 단계에서 지시 대상과 학과·학년 등의 조건을 독립 질문으로 재구성합니다. 주제·조건 변경은 최신 질문을 우선하며, 대상을 특정하지 못하면 `ambiguous_followup` 사유로 되묻고 검색·최종 답변 생성을 건너뜁니다. 재구성한 질문으로 기간 필터나 벡터 검색을 새로 수행하므로 이전 답변은 공식 근거로 재사용하지 않습니다. 맥락이 있는 요청은 모델 호출이 한 번 추가됩니다.

`conversation`은 최대 5개 `{question, answer}` 항목이며 질문 1,000자·답변 6,000자로 제한합니다. 브라우저는 긴 답변을 맥락 전달 시 6,000자로 자릅니다. `include_history`는 지난 학사일정 포함 여부이며 대화 기록과 별개의 옵션입니다. Langfuse가 켜져 있으면 전달된 대화도 trace에 기록됩니다.

`LANGFUSE_ENABLED=true`를 설정하면 질문·검색 근거·답변이 지정한 Langfuse 서버에 기록됩니다. 기본값은 비활성화이며, 기록 범위와 평가 실행 방법은 [EVALUATION.md](EVALUATION.md)를 참고하세요.

현재 모집 활동은 `GET /api/programs` 또는 “지금 신청 가능한 비교과·취업 프로그램” 질문으로 조회할 수 있습니다. 실제 수집 제한과 신청 기간 기준은 [PROGRAMS.md](PROGRAMS.md)를 참고하세요. 유효한 자료가 없으면 모집이 없다고 단정하지 않고 원문 확인을 안내합니다.

## API

### `POST /api/chat`

```json
{
  "question": "복수전공 신청 기간과 신청 방법을 알려줘",
  "include_history": false,
  "conversation": []
}
```

응답은 기존 CLI와 동일하게 `answer`, `sources`, `as_of`, `reason`, `generation_used`, `model`을 반환합니다. 출처에는 `id`, `title`, `url`, `published_at`이 있습니다. 기준일은 서버의 Asia/Seoul 날짜를 사용합니다.

- `200`: 답변 또는 근거 부족 안내. `sources`가 빈 배열일 수 있습니다.
- `400/422`: 질문 형식·길이 오류.
- `429`: API 프로세스의 동시 요청 한도 초과.
- `503`: API 키 미설정·빈 색인·생성 서비스 지연.
- `502`: 검색 또는 생성 중 처리하지 못한 오류. 내부 예외는 브라우저에 노출하지 않습니다.

API 프로세스당 최대 2개 질문을 동시에 처리합니다. 화면은 자동 재시도하지 않으며, 실제 질문에는 임베딩·답변 생성 API 비용이 발생합니다.

### `GET /health`

`{"status":"ok"}`를 반환하는 프로세스 생존 확인용 경로입니다. OpenAI나 ChromaDB 연결·색인 준비 상태를 확인하지는 않습니다. 색인 상태는 기존 `python -m semo.index_cli --status`로 확인하세요.

## 범위

이 구성은 `127.0.0.1:8001`로 바인딩한 로컬 사용용입니다. 로그인·학생 인증·사용자별 할당량·공개 배포는 아직 포함하지 않았습니다. 외부 공개 전에 인증과 공통 요청 한도를 정해야 합니다. 스트리밍은 후속 작업입니다.

요청에 따라 테스트를 작성하거나 실행하지 않았으며, 이번 API와 화면의 실제 컨테이너 기동·브라우저 동작은 아직 확인하지 않았습니다.

## 수집 자료 관리 화면

```bash
docker compose up --build -d api
```

**http://localhost:8001/admin/documents**를 열거나 챗봇의 사이드바에서 **수집 자료 관리**를 선택하세요. 모바일에서는 위 주소로 직접 접속할 수 있습니다.

- 학사일정·학사안내·공지·취업/비교과의 건수 확인
- 제목 검색, 종류와 색인 상태 필터
- 제목 선택 후 추출 본문·표·메타데이터와 원문 링크 확인
- 원문 기준 예상 청크와 실제 청크 수, 누락·이전 청크 비교
- 이미지뿐이거나 빈 본문인 문서는 **색인 제외**, 원문과 다르면 **갱신 필요**로 표시
- Chroma 연결 실패 시 원문 목록을 유지하며 색인은 **미확인**으로 표시

새로고침은 저장된 자료를 다시 읽으며 크롤링이나 색인을 실행하지 않습니다. 상태 조회 시각과 문서별 수집 확인 시각은 서로 다르며 한국 시간으로 표시합니다. 이미지는 불러오지 않고 HTML·스크립트는 실행하지 않습니다. 추출된 본문은 텍스트로, 표는 저장한 셀의 rowspan/colspan으로 표시합니다. 작성일이 없는 학사안내에는 수집 시각을 작성일로 대신 표시하지 않습니다.

화면은 `GET /api/admin/documents`의 목록·색인 상태와 `GET /api/admin/document?id=...`의 개별 원문을 사용합니다. PostgreSQL/Chroma를 조회하며 OpenAI 키나 유료 호출이 필요하지 않습니다. 문서 목록은 현재 수백 건 규모를 기준으로 한 번에 받아 브라우저에서 필터링합니다. 본문은 항목을 선택할 때만 요청합니다. PostgreSQL 연결이 실패하면 오류를 표시하며, Chroma 상태 확인 실패를 색인 누락으로 단정하지 않습니다. 목록과 상세는 서로 다른 시점의 조회이므로 수집/색인 진행 중이라면 새로고침 후 다시 확인하세요.

현재 로컬용 Compose의 `127.0.0.1:8001` 바인딩을 사용합니다. 관리자 인증은 포함하지 않았으므로 공개 배포 전에 관리 화면과 API의 접근 제어를 추가해야 합니다. 이 화면에서는 DB 스키마·문서·검색 컬렉션을 생성/수정/삭제하지 않습니다.

## 후속 질문 확인

API 재빌드 후 실제 서버 `http://localhost:8001`에서 다음 순서로 확인합니다.

1. `컴퓨터공학과 3학년이 현재 신청 가능한 비교과 활동을 알려줘`
2. `그중 온라인으로 하는 건?` — 학과·학년과 현재 신청 조건 유지
3. `두 번째 건 어떻게 신청해?` — 직전 답변의 실제 목록 순서로 대상 식별(번호가 불명확하면 되묻기)
4. `4학년 기준으로 알려줘` — 최신 학년 조건으로 변경
5. 대화 지우기 후 `그 프로그램은?` — 이전 대화를 참조하지 않아야 함

기능 확인과 별도로 실제 모델이 조건을 정확히 재구성했는지는 Langfuse의 `semo.rewrite` input/output과 `semo.retrieve`의 재구성 질문으로 확인합니다. 모델의 지시 대상 해석은 오류가 날 수 있으며, 기존 답변 인용 검증은 그대로 유지됩니다.
