# 웹 채팅과 HTTP API

CLI에서 사용하던 검색·출처 기반 답변을 브라우저에서도 사용할 수 있습니다. `semo/chat.py`의 동일한 처리 흐름을 CLI와 FastAPI가 함께 사용합니다. 별도의 프런트엔드 프레임워크나 빌드 과정 없이 HTML·CSS·JavaScript를 API 서버에서 제공합니다.

## 실행

기존 `.env`의 `OPENAI_API_KEY`, `OPENAI_CHAT_MODEL`, `POSTGRES_PASSWORD`를 유지합니다. ChromaDB v2 색인에 자료가 들어 있어야 실제 답변을 받을 수 있습니다.

```sh
docker compose up --build -d api
```

브라우저에서 **http://localhost:8001**을 열면 됩니다. API 문서는 **http://localhost:8001/docs**, 서버 로그는 다음 명령으로 확인합니다.

```sh
docker compose logs --tail=100 api
```

`api`는 기존 Dockerfile과 Python 의존성을 재사용하고, Airflow 프로세스와 별도 컨테이너에서 실행합니다. ChromaDB를 조회하며 PostgreSQL이나 원문 파일을 수정하지 않습니다. 기존 수집·색인 DAG는 그대로 사용합니다.

## 화면에서 할 수 있는 일

- 질문 예시 선택·질문 입력·답변 확인.
- 답변별 공식 출처와 게시일·답변 기준일 확인.
- 종료된 학사일정을 검색에 포함할지 선택.
- 답변 대기·연결 오류·요청 지연 안내.
- 현재 탭의 질문·답변 화면 지우기.

질문은 1~1,000자로 제한합니다. Enter로 전송하고 Shift+Enter로 줄을 바꿉니다. 한글 조합 확정 Enter는 전송으로 취급하지 않습니다. 답변을 기다리는 동안 중복 전송은 막습니다. 답변과 출처 제목은 HTML로 해석하지 않고 텍스트로 표시합니다.

각 질문은 독립적으로 처리합니다. 이전 질문을 서버에 대화 맥락으로 전달하지 않으며, 앱에서 질문·답변 이력을 별도로 저장하지 않습니다. 새로고침하면 화면의 대화가 사라집니다. API 키는 브라우저에 전달하지 않습니다.

## API

### `POST /api/chat`

```json
{
  "question": "복수전공 신청 기간과 신청 방법을 알려줘",
  "include_history": false
}
```

응답은 기존 CLI와 동일하게 `answer`, `sources`, `as_of`, `reason`, `generation_used`, `model`을 반환합니다. 출처에는 `id`, `title`, `url`, `published_at`이 있습니다. 기준일은 서버의 Asia/Seoul 날짜를 사용합니다.

- `200`: 답변 또는 근거 부족 안내. `sources`가 빈 배열일 수 있습니다.
- `400/422`: 질문 형식·길이 오류.
- `429`: API 프로세스의 동시 요청 한도 초과.
- `503`: API 키 미설정·빈 색인·생성 서비스 지연.
- `502`: 검색 또는 생성 중 처리하지 못한 오류. 내부 예외는 브라우저에 노출하지 않습니다.

API 프로세스당 최대 2개 질문을 동시에 처리합니다. 화면은 자동 재시도하지 않으며, 실제 질문에는 임베딩·답변 생성 API 비용이 발생합니다.

### `GET /health`

`{"status":"ok"}`를 반환하는 프로세스 생존 확인용 경로입니다. OpenAI나 ChromaDB 연결·색인 준비 상태를 확인하지는 않습니다. 색인 상태는 기존 `python -m semo.index_cli --status`로 확인하세요.

## 범위

이 구성은 `127.0.0.1:8001`로 바인딩한 로컬 사용용입니다. 로그인·학생 인증·사용자별 할당량·공개 배포는 아직 포함하지 않았습니다. 외부 공개 전에 인증과 공통 요청 한도를 정해야 합니다. 대화 맥락 유지·스트리밍도 후속 작업입니다.

요청에 따라 테스트를 작성하거나 실행하지 않았으며, 이번 API와 화면의 실제 컨테이너 기동·브라우저 동작은 아직 확인하지 않았습니다.
